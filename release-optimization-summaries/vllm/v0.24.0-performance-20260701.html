按主线理解

模型专用路径

DeepSeek-V4 和 MiniMax-M3 是这次最明显的模型主线：sparse index、chunk planning、topK、KV allocation、FP8/MXFP4 和 AMD/XPU/SM100 路径都在围绕大 MoE serving 落地。

硬件专用 kernel

NVIDIA、ROCm、XPU、CPU/RISC-V 都有各自优化。vLLM 在同一 release 里把 kernel backend、低精度 GEMM、MoE router 和 attention decode 都继续硬件化。

分布式 serving

DeepEP v2、NIXL KV push、Mooncake PP-PD、async lookup 和 compact chunk-hash 说明重点不只是单卡吞吐，而是宽 EP 与 PD 分离的生产服务效率。

执行器与量化

MRv2 默认支持量化模型，DFlash 进入 MRv2；量化侧补齐 PTPC、modelopt_mixed 和 Thor FP8 MoE，使低精度 serving 覆盖更多设备代际。

后续跟踪建议

  • 对 DSv4：优先复测 #45863、#45061、#43008 三个 PR 在本地 workload 的 TTFT、E2E throughput 和 low-latency TPOT 上是否能复现 release notes 收益。
  • 对 WideEP / PD：跟踪 #41183、#35264、#44528 与 Mooncake 后续 PR 的稳定性，尤其是跨节点 KV transfer 和 scheduler lookup 开销。
  • 对硬件后端：把 NVIDIA FP8 odd-M、H100 fused_moe、ROCm fused router 和 XPU W4A16 MoE 分开评估，避免把不同硬件的优化收益混到一个结论里。
  • 对量化：关注 PTPC、modelopt_mixed、NVFP4/MXFP8 kernel 与模型权重格式之间的兼容边界。
