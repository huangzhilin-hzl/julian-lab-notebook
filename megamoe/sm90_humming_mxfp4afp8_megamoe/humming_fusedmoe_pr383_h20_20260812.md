# PR383 workload：Humming MXFP4A-FP8 FusedMoE H20 结果

## 结论

- 正式 r2 矩阵 22/22 case 成功，66/66 observation 有效；每个 case 取三次 `max_rank_us` 的中位数，每次 observation 含 5 次 warmup、20 个 sample，并取 8 rank 的最大值。全部 observation 的实际 L2 flush 下限精确为 8,000,000,000 bytes。
- Humming FusedMoE 在这 22 个 H20 case 中没有快过 PR383 MegaMoE。最接近的是 Pro M=8：768.288 vs 768.0 μs（1.000×，差 +0.04%）。Flash/Pro 全 M 的几何平均分别为 PR383 MegaMoE 的 2.011×/2.036×。
- 最大差距是 Flash M=64 的 3.626×、Pro M=128 的 4.096×。小 M 的主要放大来自 INDEXED scheduler 按活跃 expert 做 BlockM padding：M=8 的 8-rank 平均有效行率只有 Flash 13.6%、Pro 13.2%。
- 这不是可互换的端到端实现：Humming 路径在每张卡复制全部 expert，计时内只有 W13 → SwiGLU/权重/FP8 重量化 → W2 → route reduce，没有 router、DeepEP dispatch/combine 或跨卡通信；PR383 MegaMoE 是 EP 执行图。表中比值用于同 shape/M/top-k 下的描述性对照，不能解释成部署替换后的端到端加速比。

## Workload 与计时口径

| Model | Hidden | Intermediate | Experts | Top-k | M |
|:---|---:|---:|---:|---:|:---|
| Flash | 4096 | 2048 | 256 | 6 | 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096, 8192 |
| Pro | 7168 | 3072 | 384 | 6 | 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096, 8192 |

| 项目 | Humming FusedMoE |
|:---|:---|
| 每 rank 输入 | `M × hidden`，每 token 随机 top-k，seed=`101 + rank` |
| 计时内 | 预量化 FP8 input → Humming INDEXED MXFP4A-FP8 W13 → Triton SwiGLU/route weight/group-128 E4M3 requant → Humming INDEXED W2 → Humming fused route reduction |
| 计时外 | input quant、权重生成/transform、route metadata、内存分配、JIT warmup |
| 统计 | 三次 observation 的 `max_rank_us` 中位数；每次为 8 rank 中最慢 rank 的 20 个 CUDA-event sample 中位数 |
| 冷缓存 | 每个 sample 前每 rank flush 8,000,000,000 bytes；flush 和 barrier 不在 CUDA event 内 |
| 通信 | NCCL 只用于 rank barrier/聚合；计时区间无 router、dispatch/combine、EP 通信 |

PR383 官方 `Speedup` 按 `DeepEP / MegaMoE - 1` 计算。本文 `Fused / MegaMoE`、`Fused / DeepEP` 小于 1 才表示 Humming 描述性延迟更低；`MegaMoE / Fused - 1` 为负表示 Humming 更慢。

## 有效性边界

- benchmark 在正式计时前检查 output shape/dtype 和 finite；本次没有 BF16/PyTorch 数值 oracle，因此性能成功不等同于数值等价证明。
- 权重和输入都是固定 seed 的合成数据；route 分布随机且可复现，没有覆盖真实模型 router 的偏斜分布。
- PR383 MegaMoE 用 `bench_kineto(..., with_multiple_kernels=True)` 统计 MegaMoE GPU kernels；Humming 用 CUDA Event 包围本地 fused-MoE 多 kernel 路径。shape 和统计聚合对齐，不代表计时工具与执行图完全相同。
- 首轮预跑误用了 8 GiB（8,589,934,592 bytes）flush，因此没有进入本文任何表格；本文只使用精确 8,000,000,000 bytes 的正式复测。
